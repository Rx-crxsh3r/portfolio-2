TypeScript Personal · Cybersecurity Done

Portcullis

A web security auditor — give it a URL, and it audits what's externally visible about the site's security posture: HTTP headers, TLS/certificate config, DNS-based email-spoofing protection (SPF/DKIM/DMARC), cookie flags, exposed sensitive files, and security.txt. Returns a letter grade with a full per-category breakdown, and tracks repeat scans of the same domain over time.

Built out of a personal interest in cybersecurity — to understand how tools like SecurityHeaders.com and the old Mozilla Observatory actually reason about "is this secure," and to get hands-on with defensive engineering that's easier to read about than to build correctly (SSRF protection, k-anonymity, DNS-rebinding resistance). Structured as three isolated pieces: a framework-agnostic /core that does pure audit logic, a thin Express /server that owns SSRF protection, rate limiting, caching and scan history, and a React/TypeScript /client that only talks to the server.

TypeScript / React Personal · Learning Done

Algorithm-Visualizer

An interactive visualizer for pathfinding (BFS, Dijkstra, A*, DFS) and sorting (bubble, insertion, merge, quick) on one shared architecture instead of two separate tools. Every algorithm is scrubbable, speed-controllable, and can be raced side-by-side against another algorithm on identical input, next to a pseudocode panel that highlights the current line as it runs.

Built to actually understand these algorithms for a college algorithms class, rather than memorize pseudocode the night before an exam — and it ended up helping a few classmates grasp the concepts more concretely, too. The core idea: every algorithm is a generator function that yields a plain "step" object whenever something meaningful happens (a node visited, an edge relaxed, a comparison, a swap) and never touches the DOM directly — which is what makes play/pause/scrub, speed control, and race mode all fall out of one ~50-line shared player instead of duplicated per-algorithm logic.
